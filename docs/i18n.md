# Local UI languages

`plak.localhost` supports English, Spanish, Portuguese and French without a
`?lang=` parameter. The language is a browser preference, not part of the URL.

## Supported locales

| Locale | Language |
|---|---|
| `en` | English |
| `es` | Español |
| `pt` | Português |
| `fr` | Français |

## How the preference works

- On first visit, `assets/i18n.js` reads `navigator.languages` (`es-AR` → `es`,
  `pt-BR` → `pt`, `fr-CA` → `fr`, `en-GB` → `en`) and falls back to English.
- The selected locale is stored in `localStorage["plak-lang"]`.
- A `plak_lang` cookie is also written with `Domain=.plak.localhost` so
  `db.plak.localhost` (Adminer) can follow the same preference. The runtime also
  writes `adminer_lang` for Adminer's own translations.
- The dashboard and editor switch instantly. The URL is never modified; the
  hash route (`#/`, `#/editor`, `#/site/<name>`) is preserved.
- The topbar switcher and the editor's compact selector use the same preference.
- Adminer starts in the selected language through `adminer_lang`; its own
  language selector remains available.

## Translation files

- `assets/lang/i18n.json` — flat dictionaries keyed by the English source
  string, with `en`, `es`, `pt` and `fr` maps. English is the fallback and only
  needs overrides for keys whose English output differs from the key (for
  example `static_plural`).
- `assets/i18n.js` — runtime that detects the locale, translates text nodes and
  the `placeholder`/`title`/`aria-label`/`alt` attributes, handles counts and
  relative times, and keeps the preference in sync.
- `scripts/build-i18n.py` — source table used to generate `i18n.json`.

The runtime skips code, preformatted output, input values, site names, paths,
mail content, plugin/theme names and other user-generated content. Raw command
output (WP-CLI, logs, email bodies) stays as-is.

## Adding a language

1. Add the locale to `SUPPORTED` and `NAMES` in `assets/i18n.js`.
2. Add the translations to `scripts/build-i18n.py` and regenerate
   `assets/lang/i18n.json`.
3. Add the option to the dashboard language menu and the editor `<select>`.
4. Add the small Adminer local-bar map in `adminer-theme/adminer.js` if the
   language should also apply there.
5. Run `bash tests/i18n.sh` and `bash tests/smoke.sh`.

## Tests

`tests/i18n.sh` validates the dictionaries, the deployed runtime, the Adminer
cookie bridge and the absence of a `lang` URL parameter. `tests/dashboard.sh`
and `tests/html-editor.sh` check that both pages load the runtime and the
switcher.
